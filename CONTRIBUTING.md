# Contributing to JSRay for VS Code

Issues and PRs are welcome. This repository is the VS Code integration; changes to
the renderer itself belong in [JSRay Core](https://github.com/jsrayorg/jsray).

## Development workflow

1. Fork and clone
2. Open the folder in VS Code and press `F5` to launch the Extension Development Host
3. In that window: **Preferences: Color Theme** → `JSRay …`, and open a Markdown preview
4. Run the tests: `npm test` (requires Node ≥ 20), then `npm run test:editor`
   — the second launches a real VS Code and asserts inside its extension host.
   Only that layer catches what the editor itself refuses: the first run of it
   found the preview never receiving the custom palette, because wrapping
   `md.render` is not an entry point the editor uses.
5. Run `npm run check:versions` and `npm run check:core` before opening a PR.
   The second asks npm whether the bundled Core snapshot is still the published
   one — the older drift check compares against a sibling checkout and skips
   when Core is absent, which is every CI run, so a stale engine used to pass a
   green build. It did: a denial of service fixed in Core sat in this bundle
   until somebody measured it.

## Do not edit synced or generated files

```text
media/jsray.js · media/jsray.css · media/themes/default.css   ← Core snapshot
palettes/*.json                                                ← Core palettes
themes/*.json                                                  ← generated by tools/build-themes.mjs
```

To change a theme color, edit the palette **in Core**, sync, and regenerate:

```sh
npm run sync:core     # pulls Core dist + palettes, then rebuilds themes
npm run build         # palettes/*.json → themes/*.json only
```

CI enforces this: a determinism gate regenerates the themes and fails if the committed
files differ, so hand-edited themes cannot merge.

Extension-owned code is `media/preview-adapter.js` and `media/markdown-preview.css`.

## Adding a theme

Themes are not authored here. Add the palette to Core's `themes/`, release it, then sync —
`tools/build-themes.mjs` fans every palette out to a dark and a light color theme, and
`tools/check-versions.mjs` verifies each generated theme is declared in `contributes.themes`.

## Versioning

`version.json` and `package.json` must agree. The Marketplace does not accept prerelease
suffixes, so `-internal.N` / `-beta.N` are stripped at publish time — the manifest keeps the
full version until then.

## Commit conventions

Short, imperative subjects, optionally scoped:

```
fix(cli): exit quietly when the downstream pipe closes early
feat: add a copy button to the block toolbar
chore: sync Core snapshot (token fallback chain)
docs: correct the language-family count
```

## Pull requests

- One PR per concern, to keep reviews easy.
- Behavior changes must come with added or updated tests — CI runs the suite on Node 18, 20, and 22, and a PR cannot merge red.
- Passing CI is necessary but not sufficient: every PR also needs maintainer review before it merges.
